# 生产部署

## 推荐拓扑

| 组件        | 建议                          |
| ----------- | ----------------------------- |
| 应用        | Vercel / 自建 Node（`start`） |
| 数据库      | Neon / Supabase / 托管 PG     |
| 邮件        | Resend + 已验证发信域名       |
| Session密钥 | 平台 Secret，≥32 字符随机     |

## 环境变量

生产必填见 [`环境变量.md`](环境变量.md)。至少：

- `DATABASE_URL`
- `SESSION_SECRET`
- `APP_URL`（HTTPS，影响 Cookie `Secure` 与邮件链接）
- `RESEND_API_KEY` + `MAIL_FROM`（找回密码）

可选：

- `LOG_LEVEL`（默认生产 `info`）
- `SENTRY_DSN`（见 [`监控.md`](监控.md)）

## 首次发布数据库

在能访问生产 `DATABASE_URL` 的环境执行：

```bash
pnpm install
pnpm exec prisma migrate deploy
pnpm db:seed   # 仅首次；生产请立刻修改种子管理员密码
```

种子账号见 [`种子数据.md`](种子数据.md)。**不要在生产长期使用默认密码。**

## Vercel 示例

1. 导入 Git 仓库，Framework Preset：**Next.js**
2. **Environment Variables** 填入上述变量
3. **Build Command**：`pnpm build`（默认即可）
4. 用 Vercel CLI 或 GitHub Action 在部署前/后执行 `prisma migrate deploy`（可用 `vercel env pull` + 一次性迁移作业）

构建阶段不需要真实 DB 连接（与 CI 相同占位 `DATABASE_URL` 也可通过 `next build`），但**运行期**必须可连库。

## Docker 全栈（简要）

1. 构建镜像：`docker build`（需自备 Dockerfile 或将 `pnpm build` + `node server` 打进镜像）
2. 同编排内启动 PostgreSQL，挂载 `DATABASE_URL`
3. 入口命令：`pnpm exec prisma migrate deploy && pnpm start`
4. 反向代理（Caddy/Nginx）终止 TLS，设置 `APP_URL`

## 发布后自检

```bash
curl -sS "$APP_URL/api/health/db" | jq
# 期望 connected: true

# 或在本机对生产跑 smoke（慎用：会写审计/会话）
```

## 回滚

- 应用：平台上一版本部署
- 数据库：Prisma 迁移一般只前进；回滚需提前备份 + 手工 down 脚本（本 MVP 未提供 down migration）
